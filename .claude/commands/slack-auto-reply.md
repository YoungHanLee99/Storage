## 1. 조회 구간 확정

- 현재 시각(KST) 기준 **최근 90분**을 조회 구간으로 잡습니다.
  (실행 주기 60분 + 지연·경계 누락 방지용 30분 오버랩)
- `date -d '90 minutes ago' +%s` 로 Unix timestamp를 구해 `after` 파라미터에 씁니다.

## 2. 수집

`slack_search_public_and_private` 사용 (DM·비공개 채널 포함).

**모든 조회에 아래 파라미터를 반드시 붙입니다.**
`sort="timestamp"`, `sort_dir="desc"`, `include_bots=false`,
`include_context=false`, `response_format="concise"`, `limit=10`
→ 빠뜨리면 응답이 5만 자를 넘어 잘립니다. (실측 확인됨)

> ⚠️ **Slack 키워드 검색은 공백을 AND로 처리합니다.**
> `계약 NDA 법무` 처럼 여러 단어를 한 쿼리에 넣으면 결과가 0건이 됩니다.
> **키워드는 반드시 한 쿼리에 하나씩**, 여러 호출로 나눠 **병렬 실행**하세요.

### 2-A. 나에게 온 DM / 그룹 DM
`query="to:me"`, `channel_types="im,mpim"`, `after=<구간 시작>`
→ 내가 보낸 메시지는 제외합니다.

### 2-B. 나를 직접 호명한 메시지
`query="<@U0ASV74BP88>"`, `after=<구간 시작>`
→ 채널·스레드 안에서 나를 멘션한 보고·질의를 잡는 가장 정확도 높은 신호입니다.

### 2-C. 내가 참여한 스레드의 새 댓글
`query="is:thread"`, `only_my_channels=true`, `after=<구간 시작>`
→ `is:thread`는 **내 채널의 모든 스레드**를 반환합니다(내 스레드만이 아님).
  각 건을 `slack_read_thread`로 열어
  ① 내가 이미 발언한 스레드인지, ② 내 마지막 발언 이후 타인의 새 댓글이 있는지
  확인해 해당하는 건만 남깁니다.

### 2-D. 법무·계약 키워드 (한 쿼리에 하나씩)
`only_my_channels=true`, `after=<구간 시작>` 으로 아래 키워드를 각각 조회합니다.
분량이 많으면 앞쪽 그룹을 우선하고, 남은 키워드는 다음 실행에서 다시 잡힙니다.

- 1순위: `계약서` `NDA` `비밀유지` `법무검토` `자문` `해지` `손해배상`
- 2순위: `컴플라이언스` `개인정보` `저작권` `상표` `라이선스` `하도급` `인허가`
- 3순위: `이사회` `주주` `정관` `실사` `MOU` `LOI` `위임장` `인감`
- 영문: `contract` `agreement` `indemnity` `liability` `compliance`
- 일문: `契約` `秘密保持` `法務` `検討`

## 3. 선별 — "회신이 필요한 건"만 남긴다

**포함**: 나에게 직접 물어본 질의 / 검토·의견·승인·서명·확인 요청 / 일정·회의 조정 요청 /
기한이 명시된 요청 / 대외(카운터파티·외부 자문사) 문의 / 내 답이 없으면 진행이 막히는 건.

**제외**:
- 단순 공유·FYI, 감사·인사치레, 이미 종결된 대화
- 봇·자동 알림(일일매출보고서, 전자결재 `[승인완료]` 통지, CI/배포 알림, 근태 알림)
- `sales_inquiry` 등 자동 배정 알림, 뉴스레터·공지·경조사 안내
- 이미 다른 담당자가 답변을 완료해 내 개입이 불필요한 건
- 다른 사람에게 명시적으로 배정된 요청(멘션 대상이 내가 아닌 건)
- 내가 이미 답변한 건 (3-1 확인)

### 3-1. 중복 방지 — 초안 생성 직전 반드시 확인

1. 대상 메시지 이후에 **내 응답이 이미 있는지** 확인합니다.
   스레드는 `slack_read_thread`, 채널·DM은 `slack_read_channel`
   (`response_format="concise"`) → 있으면 건너뜁니다.
2. `slack_send_message_draft`가 `draft_already_exists`를 반환하면
   해당 채널에 사용자가 아직 처리하지 않은 초안이 있다는 뜻입니다.
   **덮어쓰지 말고** 건너뛰고 "기존 초안 대기 중"으로 기록합니다.
3. Slack은 **채널당 attached draft 1건**만 허용합니다.
   같은 채널에 후보가 여러 건이면 가장 중요·긴급한 건 하나로 합쳐 작성합니다.

## 4. 초안 작성 규칙

- **언어 미러링**: 상대가 쓴 언어로 작성합니다 (한국어 / English / 日本語).
- **길이**: 기본 3~6문장. 다항목 보고에 대한 회신은 항목별 소제목(`*1. ...*`)을 두고
  항목당 1~3문장으로 구성합니다.
- **형식**: Slack mrkdwn(`*굵게*`, `_기울임_`, `•`)을 사용하고 마크다운 헤더·표는 쓰지 않습니다.
- **구조**: 짧은 수신 확인 → 핵심 답변 또는 현재 입장 → 필요한 액션·담당·기한 → 마무리.
- **톤**: 사내는 간결한 존대, 대외는 격식체. CSO·General Counsel 명의로 나가는 글임을 전제합니다.
- **첫 줄에 아래 마커를 반드시 넣습니다** (사용자가 전송 전에 삭제):

  `〔AI 초안 · 검토 후 이 줄을 삭제하고 전송〕`

### 법무 리스크 가드레일 (필수)

- **확약·승인·법적 결론을 단정하지 않습니다.** 확정 권한이 필요한 사안은
  "검토 후 회신드리겠습니다" / "확인하여 별도 안내드리겠습니다" 수준으로 남깁니다.
- **원문 문서를 직접 확인하지 못한 계약·NDA 건은 결론을 쓰지 않습니다.**
  대신 수신 확인 + 검토 배정 + 확인해야 할 쟁점 목록 + 회신 시점으로 구성합니다.
- 금액·기한·당사자·조항 번호 등 **사실관계가 불확실한 값은 절대 추정하지 않고**
  `[확인 필요: 금액]` 형태의 플레이스홀더로 둡니다.
- 계약 해지·위반·손해배상·분쟁 등 **대외 리스크 사안**은 실체적 입장을 쓰지 않고
  보수적 수신 확인 초안만 작성합니다.
- Slack Connect(외부 공유) 채널·게스트 상대 초안은 한 단계 더 보수적으로 작성하고,
  대외비 정보(금액, 내부 의사결정 과정, 다른 거래 건)를 포함하지 않습니다.
- 맥락이 부족하면(첨부 미확인·배경 불명) 초안을 만들지 말고
  "맥락 부족 — 수동 확인 필요"로만 보고합니다.

## 5. 초안 저장

`slack_send_message_draft`:
- `channel_id`: 대상 채널 ID (1:1 DM은 상대 `user_id`, 그룹 DM은 `C...` 형태의 mpim ID)
- `thread_ts`: 스레드 내 회신이면 **부모 메시지 ts를 반드시 지정**
  (지정하지 않으면 채널 본문에 새 글로 남습니다)
- `message`: 4항 규칙대로 작성한 본문

`channel_not_found` / `not_in_channel` → 건너뛰고 사유를 기록합니다.
