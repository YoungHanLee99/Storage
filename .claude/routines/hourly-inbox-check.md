# Routine 프롬프트: `Hourly inbox check` (확장판)

**용도**: claude.ai → Routines → `Hourly inbox check`(`58 * * * *`)를 열어
아래 코드블록 안의 내용을 **프롬프트란에 그대로 붙여넣기** 하면 됩니다.

**왜 수동인가**: Routine이 띄우는 세션은 그 Routine에 저장된 커넥터만 씁니다.
Claude Code 세션에서 만든 Routine에는 Slack 커넥터를 붙일 수 없고(조직 정책),
claude.ai UI에서 만든 Routine은 에이전트가 수정할 수 없습니다
(`update_trigger`: *agents can only update routines they created*).
`Hourly inbox check`는 Gmail·Google Calendar·Google Drive·**Slack** 커넥터를 이미 보유한
유일한 정상 동작 Routine이므로, 여기에 붙이는 것이 가장 확실합니다.

기존 A파트(이메일·슬랙 요약 보고)는 그대로 유지하고 B파트(답신 초안 저장)만 더한 형태입니다.

# A. 이메일·슬랙 요약 보고

1. 최근 1시간 내 미열람 이메일과 슬랙 메시지를 확인합니다.
2. 전략기획실 또는 이영한 실장 앞으로 온 업무·요청·액션 아이템을 추립니다.
3. 발신자, 주제, 명시된 기한·우선순위를 붙여 사용자에게 요약 보고합니다.
4. 새로운 관련 메시지가 없으면 간단히 확인만 알립니다.

# B. 슬랙 답신 초안 저장

**메시지를 절대 전송하지 마세요.** `slack_send_message_draft`로 초안만 저장합니다.

## B-1. 조회 구간
`date -d '90 minutes ago' +%s` 로 구한 Unix timestamp를 모든 검색의 `after`로 씁니다. (주기 60분 + 경계 누락 방지 30분 오버랩)

## B-2. 수집 — `slack_search_public_and_private`
모든 검색에 다음을 반드시 붙입니다: `sort="timestamp"`, `sort_dir="desc"`, `include_bots=false`, `include_context=false`, `response_format="concise"`, `limit=10`. 빠뜨리면 응답이 5만 자를 넘어 잘립니다.

**Slack 키워드 검색은 공백을 AND로 처리합니다. 키워드는 반드시 한 쿼리에 하나씩 넣어 여러 호출로 병렬 실행하세요.** 여러 단어를 한 쿼리에 넣으면 결과가 0건이 됩니다.

- **나에게 온 DM/그룹DM**: `query="to:me"`, `channel_types="im,mpim"` → 내가 보낸 건 제외
- **나를 직접 호명한 메시지**: `query="<@U0ASV74BP88>"` → 정확도가 가장 높은 신호
- **내가 참여한 스레드의 새 댓글**: `query="is:thread"`, `only_my_channels=true` → `is:thread`는 내 채널의 모든 스레드를 반환하므로, 각 건을 `slack_read_thread`로 열어 ①내가 이미 발언한 스레드인지 ②내 마지막 발언 이후 타인의 새 댓글이 있는지 확인해 해당 건만 남깁니다
- **법무·계약 키워드** (`only_my_channels=true`, 키워드 1개씩 개별 호출): `계약서` `NDA` `비밀유지` `법무검토` `자문` `해지` `손해배상` `컴플라이언스` `개인정보` `저작권` `상표` `라이선스` `하도급` `인허가` `이사회` `주주` `정관` `실사` `MOU` `LOI` `contract` `agreement` `indemnity` `liability` `compliance` `契約` `秘密保持` `法務`

## B-3. 선별 — "회신이 필요한 건"만
**포함**: 나에게 직접 물어본 질의 / 검토·의견·승인·서명·확인 요청 / 일정 조정 요청 / 기한 명시 요청 / 대외(카운터파티·외부 자문사) 문의 / 내 답이 없으면 진행이 막히는 건.

**제외**: 단순 공유·FYI, 감사·인사치레, 종결된 대화, 봇·자동알림(일일매출보고서, 전자결재 `[승인완료]`, `sales_inquiry` 자동배정, CI/배포, 근태), 뉴스레터·공지·경조사, 이미 다른 담당자가 답변 완료한 건, 멘션 대상이 내가 아닌 건.

**중복 방지 — 초안 생성 직전 필수**
1. 대상 메시지 이후 **내 응답이 이미 있는지** `slack_read_thread` / `slack_read_channel`(`response_format="concise"`)로 확인 → 있으면 건너뜁니다.
2. `draft_already_exists` 반환 시 사용자가 아직 처리하지 않은 초안이 있다는 뜻 → **덮어쓰지 말고** 건너뛰고 "기존 초안 대기 중"으로 기록합니다.
3. Slack은 채널당 attached draft 1건만 허용합니다. 같은 채널에 후보가 여러 건이면 하나로 합쳐 작성합니다.

## B-4. 초안 작성
- 상대가 쓴 언어로 작성 (한국어/English/日本語)
- 기본 3~6문장. 다항목 보고 회신은 항목별 소제목(`*1. ...*`) + 항목당 1~3문장
- Slack mrkdwn(`*굵게*`, `_기울임_`, `•`) 사용, 마크다운 헤더·표 금지
- 구조: 수신 확인 → 핵심 답변/현재 입장 → 필요한 액션·담당·기한 → 마무리
- 톤: 사내는 간결한 존대, 대외는 격식체. CSO·General Counsel 명의 전제
- **첫 줄에 반드시**: `〔AI 초안 · 검토 후 이 줄을 삭제하고 전송〕`

**법무 리스크 가드레일 (필수)**
- 확약·승인·법적 결론을 단정하지 않습니다. "검토 후 회신드리겠습니다" 수준으로 남깁니다.
- **원문 문서를 직접 확인하지 못한 계약·NDA 건은 결론을 쓰지 않습니다.** 수신 확인 + 검토 배정 + 확인해야 할 쟁점 목록 + 회신 시점으로 구성합니다.
- 금액·기한·당사자·조항 번호 등 불확실한 값은 **절대 추정하지 않고** `[확인 필요: 금액]` 형태로 둡니다.
- 계약 해지·위반·손해배상·분쟁 등 대외 리스크 사안은 실체적 입장 없이 보수적 수신 확인 초안만 작성합니다.
- Slack Connect(외부 공유)·게스트 상대 초안은 한 단계 더 보수적으로, 대외비(금액·내부 의사결정 과정·다른 거래 건) 미포함.
- 맥락 부족(첨부 미확인·배경 불명) 시 초안을 만들지 말고 보고만 합니다.

## B-5. 저장
`slack_send_message_draft(channel_id, message, thread_ts)`
- 1:1 DM은 상대 `user_id`, 그룹 DM은 `C...` mpim ID
- 스레드 회신이면 **부모 메시지 ts를 `thread_ts`에 반드시 지정** (없으면 채널 본문에 새 글로 남습니다)
- `channel_not_found` / `not_in_channel` → 건너뛰고 사유 기록

## 붙여넣은 뒤 확인 방법

1. Routine을 한 번 수동 실행(Run now)합니다.
2. 실행 시간이 **1분 이상** 걸리는지 봅니다.
   Slack 커넥터가 없으면 20~30초 만에 끝납니다 (실측: 커넥터 없는 Routine은 22초 만에 종료).

## 24시간 실행에 대한 참고

`Hourly inbox check`는 `58 * * * *` — 요일·시간 제한 없이 매시 58분에 돕니다.
평일 업무시간으로 좁히려면 UI에서 cron을 `58 23 * * 0-4` + `58 0-11 * * 1-5` 로 나누거나
(KST 08:58 / 09:58~20:58), 단순하게 `58 0-11 * * 1-5`(KST 09:58~20:58)만 두면 됩니다.
